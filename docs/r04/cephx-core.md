# R04 CephX Authentication And Secure Sessions

This phase ports the deterministic CephX authentication mechanics from the
pinned Go oracle at `c8bb148a1379b51ef87256c27f366a05f8da4dc4` and integrates
them with private monitor and service connectors. The ordinary public `Client`
is not wired to these connectors in R04.

## Provenance

The imported P03 fixtures in `testdata/p03` retain their original byte content
and SHA-256 identities. Their manifests record Ceph `v20.2.4` commit
`7f793731f1b39eb4f465e960113d2363c311b964`, the digest-pinned Ceph image,
source-file hashes, generator versions, redistribution approval, and the pinned
Go import source. `cephx-encoding-vectors.json` was generated by
`ceph-dencoder`; `crypto-vectors.json` combines an OpenSSL AES-128-CBC result,
an RFC 8009 published vector, and a synthetic challenge result.

The Rust implementation uses maintained RustCrypto `aes`, `cbc`, `hmac`, and
`sha2` crates. RFC 8009 AES256-CTS-HMAC-SHA384-192 key derivation and CTS block
ordering are tested against the imported independent vector. Ceph key usages
`0x03`, `0x04`, `0x05`, `0x10`, `0x11`, and `0x12` remain explicit and distinct.

## Security Boundary

Keys accept only canonical 16-byte type-1 or 32-byte type-2 values. All decode
and allocation paths apply configured limits, authenticated type-2 ciphertext
is verified before decryption, and envelope version and magic are checked before
plaintext is returned. Secret-bearing values redact `Debug` and `Display`;
owned key, ticket, authorizer, connection-secret, and temporary plaintext
buffers are zeroized where practical.

CBC is retained only for Ceph protocol compatibility. Its fixed IV and padding
are not independently authenticated, so callers must use the checked CephX
magic envelope. Type-2 encryption takes an explicit confounder in this
deterministic core; the connectors source fresh confounders and challenges from
the operating system RNG. Transcript signatures use HMAC-SHA-256 and are
verified in constant time by the RustCrypto implementation.

## Connector Boundary

The monitor connector performs bounded messenger v2.1 banner, Hello and CephX
exchanges, verifies transcript signatures before enabling the secure codec and
rejects secure-to-CRC downgrade unless CRC is explicitly selected. Successful
authentication publishes the global ID, ticket set and connection secret as one
transaction; failed, cancelled and timed-out attempts preserve prior state.

The service connector builds and verifies CephX authorizers for OSD and manager
services, including challenge replies and rotated tickets. Expiry and renewal
feed the generation-tagged R03 session owner. Scripted duplex tests cover both
connectors; the pinned live gate covers monitor authentication, identity,
same-session renewal, ticket rotation and expiry, reconnect, wrong-key denial
and downgrade denial. Live OSD and manager authorization remain an R05+ gate.

The feature-gated `rados-r04-live` binary exists only for qualification. It does
not widen the ordinary library API or enable network features by default.
