# Security Policy

## Supported Versions

No version has been released or tagged. Until a release policy is established,
only the current default branch is considered for security fixes, on a
best-effort basis. Historical commits and downstream forks are not supported.
This policy does not make the unreleased default branch production-ready.

## Reporting a Vulnerability

Use GitHub private vulnerability reporting for this repository:

<https://github.com/otuschhoff/go-librados/security/advisories/new>

Include the affected commit or version, impact, prerequisites, reproduction or
proof of concept, and any suggested mitigation. Do not include reusable CephX
keys, tickets, session secrets, production FSIDs, object payloads, or other
third-party secrets. Use synthetic or redacted data.

Do not open a public issue for an undisclosed vulnerability. If GitHub private
vulnerability reporting is unavailable, there is currently no alternative
private contact published by the project; do not send sensitive details through
a public channel. A maintainer must add and verify an alternative contact before
one can be documented here.

Receipt, remediation, disclosure, or response-time targets are not guaranteed.
Reports will be assessed against the qualified compatibility matrix, but issues
outside that matrix may still be relevant and should be reported privately.
